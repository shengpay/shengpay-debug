绑卡 / 解绑结果异步通知 · 接入要点

      
调用「H5快捷绑卡管理」时传入 notifyUrl，或在「H5快捷支付收单」的 extra.bindCardEventNotifyUrl 中传入通知地址后，用户在 H5 收银台完成绑卡或解绑时，平台将以 HTTP POST JSON 方式向该地址发送异步通知。

      
    
        
  • 1通知使用平台私钥对报文字段加签，商户须用平台公钥验签后再处理业务。
    • 
        
  • 2收到通知后必须返回字符串 SUCCESS（纯文本、HTTP 200），平台以此判断接收成功；返回其他内容或超时均视为通知失败，当前版本不做自动重试。
    • 
        
  • 3通知不阻断用户侧绑卡/解绑主流程——即使通知失败，用户操作结果依然有效。
    • 
        
  • 4卡号仅返回后四位，不返回完整卡号或前六后四。
    • 
        
  • 5请使用 Map / 字典等对象接收，先验签、再做业务处理，避免固定对象接收导致后续新增字段时验签失败。
    • 
      

    

    

      

        
服务端应答示例 · Node.js

        

          
NODE · VERIFY & ACK


// 快捷绑卡事件通知：先验签、再处理，最后纯文本返回 SUCCESS
const crypto = require('crypto');

app.post('/bindcard/notify', async (req, res) => {
  const body = req.body;                    // Map/字典式接收，勿映射固定对象
  const { sign, ...data } = body;

  // 待验签串拼接规则、摘要算法以平台文档为准（示例为字段排序后 JSON 化）
  const raw = JSON.stringify(sortByKey(data));
  const ok = crypto.verify(
    'RSA-SHA256',
    Buffer.from(raw),
    PLATFORM_PUBLIC_KEY_PEM,               // 平台公钥（验签用）
    Buffer.from(sign, 'base64')
  );
  if (!ok) return res.status(400).send('FAIL');

  // 验签通过后再处理业务：body.event 为绑卡/解绑事件，
  // 卡号仅后四位（cardNoLast4），cardType 为 CC(贷记)/DC(借记)
  await handleBindCardEvent(body);

  res.send('SUCCESS');                      // 必须纯文本 SUCCESS + HTTP 200
});

签名流程说明

        

          ① 生成报文时按《签名介绍》规则拼接 stringA：非空参数值按参数名 ASCII 字典序 key=value&…，剔除 sign 与空值（signType 参与），extra / detail 按原文；

          ② 使用商户私钥对待签串做 RSA-SHA256（或 SHA1）签名，Base64 后写入 sign；

          ③ 「签名详情」面板展示待签串与签名值，待签串可编辑后重新签名并回填报文；

          ④ 若平台验签失败，优先核对待签串拼接规则（如 extra 嵌套对象是否参与、空值处理）与算法是否与文档一致。
